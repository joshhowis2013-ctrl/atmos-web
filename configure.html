Atmos Web documentation

Configure it once. Then check the sky.

Use this guide to run Atmos Web locally, connect optional Met Office warnings, deploy the static site to GitHub Pages, and attach a custom domain.

Open dashboard →Open pressure map

1. Run locally on Ubuntu/Linux

Atmos Web is developed and tested on Ubuntu/Linux. Node.js is required for the full server and optional warning proxy.

sudo apt update
sudo apt install nodejs npm
cd ~/weather-app
npm install
npm start

Open http://localhost:3000. The dashboard is at the root, and this documentation page is available at /configure.html.

2. Download and install

Choose one of the two download options below. Do not run both.

Option A: Clone with Git

Use this option if Git is installed and you want to receive future updates with git pull.

sudo apt update
sudo apt install git nodejs npm
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/joshhowis2013-ctrl/atmos-web.git
cd atmos-web
npm install

Option B: Download a ZIP

  1. Open the repository on GitHub.
  2. Select Code → Download ZIP.
  3. Save the ZIP in your Downloads folder and extract it.
  4. Open a terminal and move into the extracted project folder.
sudo apt update
sudo apt install nodejs npm
mkdir -p ~/Projects
unzip ~/Downloads/atmos-web-main.zip -d ~/Projects
cd ~/Projects/atmos-web-main
npm install
If you downloaded a ZIP, run npm install again whenever the dependencies in package.json change.

3. Configure the environment file

Copy the safe template. The real file is ignored by Git and must never be committed.

cp .env.example .env
nano .env

The normal weather forecast works without an API key. Only add Met Office settings if you have enabled the warnings product.

PORT=3000
MET_OFFICE_WARNINGS_URL=https://your-warnings-endpoint
MET_OFFICE_API_KEY=your-rotated-api-key
MET_OFFICE_AUTH_HEADER=X-API-Key
Never put a private API key in app.js, HTML, or GitHub Pages. If a key is exposed, rotate it immediately.

4. Enable Met Office warnings

  1. Create an account at the Met Office Weather DataHub.
  2. Open the warnings or NSWWS product documentation and copy its exact endpoint.
  3. Set the endpoint, credential, and required authentication header in .env.
  4. Restart Atmos Web with npm start.

The dashboard keeps working if the warning proxy is unavailable. It will show the official Met Office link instead.

5. Choose where to host

You do not need GitHub Pages to use Atmos Web. Choose the option that matches how you want to run it.

Run it locally

cd ~/weather-app
npm start

Use http://localhost:3000 for your own computer or local network.

Use a Node.js host

Choose a host that supports Node.js if you want the secure Met Office warning proxy. Set the start command to npm start and add the values from .env as encrypted environment variables in the host dashboard.

Use static hosting

GitHub Pages, Netlify, Cloudflare Pages, and similar static hosts can serve the forecast website without the Node proxy. Search, animations, the PWA, and Open-Meteo weather work there; live private Met Office proxy requests need a separate Node service.

6. Optional GitHub Pages deployment

  1. Push the repository to GitHub.
  2. Open Settings → Pages.
  3. Choose GitHub Actions as the deployment source.
  4. Push to main or run Deploy Atmos Web to GitHub Pages in the Actions tab.

This is optional. The repository already includes a deployment workflow, but GitHub Pages cannot run server.js or store private Met Office credentials.

7. Connect a custom domain (Optional)

Configure the domain at the hosting provider you choose. Point the domain to that provider, enable HTTPS, and make sure the host serves index.html at the root.

https://your-domain.com/              dashboard
https://your-domain.com/overview.html overview
https://your-domain.com/configure.html documentation

For GitHub Pages specifically, use Settings → Pages → Custom domain and add the DNS records GitHub provides.

8. Update Atmos Web safely

cd ~/weather-app
git pull origin main
npm install
npm start

After changing .env, restart the server. After changing a cached frontend file, the service worker updates its cache version in sw.js.

9. Troubleshooting

  • Port already in use: stop the existing server or run PORT=3001 npm start.
  • Warnings unavailable: confirm the endpoint, authentication header, and rotated API key in .env.
  • Pages shows a 404: enable GitHub Pages with GitHub Actions as the source, then rerun the workflow.
  • Changes do not appear: refresh the page, clear the site cache, or wait for the service worker to update.
  • Location does not work: allow browser location access or search for a city instead.

10. Keep credentials private

Check before every push:

git status
git check-ignore -v .env
git grep -n "MET_OFFICE_API_KEY" -- ':!.env.example'

The real key should only exist in local environment variables or your hosting provider's secret manager.
